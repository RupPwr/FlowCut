SECTION 0: IS SPEC KA MAQSAD AUR KYA NAHI BADLEGA
==================================================

Maqsad
- Timeline aur playhead ko ek patla, sthir core banana. Audio, text, transition, speed, trim jaise saare features is core ke bahar plug-in ki tarah jude.
- Features ki ginti badhne se timeline par dabav na badhe. Dabav sirf "screen par dikhne wale items" aur "us pal chalu items" par nirbhar kare.
- Jitter ki jad (playhead aur scroll ka do jagah se badalna) khatam ho.

Sachchai (jaan-boojh kar likhi hai)
- "100 features ke baad bhi bilkul wahi dabav" ka wada koi nahi kar sakta.
- Jo pakka kiya ja sakta hai: dabav features ki ginti par nahi, sirf dikhne wale aur chalu items par depend kare. Isse Section 12 ka scale test har baar jaanchega.

Jo is spec mein NAHI badlega (jaisa hai waisa rahega)
- FrameSource aur video decoder ke niyam (decoder pool, prefetch, latest-wins seek, generation token).
- Import ke niyam (1080p, 15 minute) aur dialog.
- Export ka frame-by-frame loop (sirf frame ka "kya chalu hai" ab naye snapshot se aayega).
- OpenGL shaders aur transitions ka rendering.
- Editor screen ka visual layout (fixed layout, rang, size).
- Audio phase (V2) ki design. Foundation ke baad usme chhota badlav hoga taaki wo plug-in ki tarah jude.

Is spec mein kya badlega
- Timeline ka data (index), playhead, vsync ka loop, timeline ka UI, edit ka tareeka (commands), aur features ke jodne ka tareeka.

SECTION 1: BADE NIYAM (12 IRON RULES)
==================================================

R1. Playhead ka time sirf ek class likhti hai (PlaybackController). Baaki sab sirf padhte hain.
R2. Scroll ka apna koi state nahi hota. Timeline ka scroll offset playhead ke time se nikalta hai, ulta kabhi nahi.

R5. Time hamesha Long mein (ms, us, audio frames). Float mein kabhi nahi.

R7. Frame ke waqt koi index build nahi hota. Sirf binary search.
R8. Timeline kisi feature ko "push" nahi karti. Har feature khud poochta hai "time t par mera kya chalu hai?" (pull).
R9. Har edit ek Command banke ek hi darwaze (EditorController.dispatch) se jaata hai.
R10. Hot path (vsync, GL draw, audio block, timeline draw) mein: koi memory allocation nahi, koi lock nahi, koi file ya JSON nahi, koi Log nahi, koi sleep nahi.
R11. Sab consumers (video, audio, baad mein waveform) clip ke andar ka time TimeMap se nikalte hain. Khud "local time" ka hisaab nahi karte.
R12. Naya feature core ki kisi file ko nahi chhuta. Wo plug-in banke (Section 10) judta hai.

SECTION 3: TIME KE UNITS
==================================================

Ek hi file: core/time/Time.kt

Kaun sa time kis unit mein
- Project model (clip, item ki position aur lambai): milliseconds, Long.
- Playhead aur frame ka time: microseconds, Long.
- Audio: frames, Long (48000 Hz par 1 ms = 48 frames).
- Pixel: Double, sirf draw ke waqt nikalta hai, kahin store nahi hota.

Code

  const val US_PER_MS = 1_000L
  const val AUDIO_FRAMES_PER_MS = 48L

  fun msToUs(ms: Long): Long = ms * US_PER_MS
  fun usToMs(us: Long): Long = Math.floorDiv(us, US_PER_MS)
  fun msToAudioFrames(ms: Long): Long = ms * AUDIO_FRAMES_PER_MS
  fun usToAudioFrames(us: Long): Long = Math.floorDiv(us * AUDIO_FRAMES_PER_MS, US_PER_MS)

Niyam
- Time, position ya duration ke liye Float ya Int kabhi nahi.
- Conversion sirf in functions se. Kahin aur "/ 1000" ya "* 1000" haath se nahi likhna.
- Overflow nahi hota: 15 minute = 900,000,000 us, audio frames = 43,200,000.
- Pixel ka hisaab: px = timeUs * pxPerUs (Double). Draw mein sirf ek baar integer pixel mein round hota hai (Section 8).

SECTION 4: PROJECT DATA MODEL (MAIN TRACK, LANES, TIMEMAP)
==================================================

Soch
- Main track: clips ek ke baad ek, beech mein junction (transition). Jaisa abhi hai.
- Lanes: baaki sab (text, music, sticker, effect) alag lanes mein, apni absolute position par.
- Jo field names abhi project mein hain (Clip.durationMs, transitions) unhe rakho. Sirf neeche likhe naye cheezein jodo, sab default value ke saath, taaki purani project.json khule.

Naye data

  @Immutable @Serializable
  data class Project(
      // ... jo pehle se hai (clips, transitions) wahi rahega ...
      val lanes: List<Lane> = emptyList()          // naya
  )

  @Immutable @Serializable
  data class Lane(
      val id: String,
      val kind: String,                            // feature ki id, jaise "text", "music"
      val items: List<LaneItem> = emptyList()
  )

  interface LaneItem {                             // har feature apna item banayega
      val id: String
      val startMs: Long                            // timeline par absolute position
      val durationMs: Long
  }

  @Immutable @Serializable
  data class TimeMap(
      val inUs: Long,                              // source mein kahan se
      val outUs: Long,                             // source mein kahan tak
      val speedNum: Int = 1,                       // speed = speedNum / speedDen
      val speedDen: Int = 1                        // abhi hamesha 1/1. Reverse (negative) abhi mana.
  ) {
      fun timelineDurationUs(): Long = (outUs - inUs) * speedDen / speedNum
      fun sourceUs(localTimelineUs: Long): Long = inUs + localTimelineUs * speedNum / speedDen
  }

  // Clip mein: val timeMap: TimeMap? = null   (null = pura clip, speed 1)
  fun Clip.map(): TimeMap = timeMap ?: TimeMap(0L, durationMs * 1000L)

Lane ke niyam
- Ek lane ke items kabhi ek doosre par chadhe nahi hote (no overlap). Items startMs se sorted rehte hain.
- Overlap chahiye to alag lane. Isse "time t par chalu item" binary search se mil jaata hai.
- Lane items timeline par absolute position par hote hain, clip se jude nahi. Main track mein ripple (clip hatana) hone par lane items apni jagah rehte hain. (Baad mein "clip se jodna" option aa sakta hai.)
- Lane item timeline ke end ke baad nikal jaaye to wo dikhta nahi (timeline ki total length sirf main track tay karti hai).
- Lane khaali ho to bhi rakhi ja sakti hai.

Unknown item type
- Agar project mein koi item type ka feature ab maujood nahi, to project corrupt nahi hona chahiye. Item skip hoga aur warning log hogi. (Abhi lanes khaali hain, isliye sirf registry mein ye hook rakhna hai, poora implementation tab jab pehla lane-feature aaye.)

TimeMap ka niyam (R11)
- Video decoder, audio source, aur koi bhi consumer clip ke andar ka time sirf clip.map().sourceUs(localTimelineUs) se nikalega.
- Trim aur speed baad mein sirf TimeMap ki values badlenge. Baaki code nahi badlega.

Invariants (har edit ke baad Validator check karta hai)
- junction/transitions ki ginti = max(0, clips.size - 1).
- Har lane mein items sorted aur no-overlap.
- Sabhi clips ki duration ka sum 15 minute se zyada nahi (import ki limit wahi).
- Har clip ki duration kam se kam 1 second.

SECTION 5: SNAPSHOT AUR INDEX (O(log n))
==================================================

Kya hai
- TimelineSnapshot project ki ek immutable tasveer hai, uske saath uske index. Ek baar ban gaya to kabhi badalta nahi.
- Har edit par naya snapshot background thread par banta hai aur SnapshotHolder.current mein ek jhatke mein badal jaata hai.

Code

  class SnapshotHolder { @Volatile var current: TimelineSnapshot = TimelineSnapshot.EMPTY }

  class TimelineSnapshot(val version: Long, val project: Project) {
      val main = MainIndex(project)
      val lanes: Array<LaneIndex> = Array(project.lanes.size) { LaneIndex(project.lanes[it]) }
      val totalMs: Long get() = main.totalMs

      fun resolve(tUs: Long, out: ActiveSet) {      // koi allocation nahi
          main.resolve(tUs, out)
          val tMs = usToMs(tUs)
          for (i in lanes.indices) out.laneItem[i] = lanes[i].indexAt(tMs)   // -1 = kuch nahi
      }
  }

  class ActiveSet(laneCount: Int) {                 // ek baar bana kar baar-baar use hota hai
      var aIndex = 0; var aLocalUs = 0L
      var bIndex = -1; var bLocalUs = 0L            // bIndex == -1 matlab transition nahi
      var type = TransitionType.NONE
      var linearP = 0f                              // transition ki progress (0..1), time nahi
      val laneItem = IntArray(laneCount) { -1 }
  }

MainIndex (abhi ke ProgramTimeline wala hi logic, sirf us mein time ab us mein)

  class MainIndex(project: Project) {
      val n = project.clips.size
      val durMs = LongArray(n) { project.clips[it].durationMs }
      val dMs = LongArray(maxOf(0, n - 1)) { project.transitions[it].durationMs }   // NONE => 0
      val types = Array(maxOf(0, n - 1)) { project.transitions[it].type }
      val startMs = LongArray(n)
      val endMs = LongArray(n)
      val totalMs: Long
      init {
          var s = 0L
          for (k in 0 until n) {
              startMs[k] = s
              endMs[k] = s + durMs[k]
              s = endMs[k] - (if (k < n - 1) dMs[k] else 0L)
          }
          totalMs = if (n == 0) 0L else endMs[n - 1]
      }
      fun lastStartAtOrBefore(tMs: Long): Int {          // binary search
          var lo = 0; var hi = n - 1; var ans = 0
          while (lo <= hi) {
              val mid = (lo + hi) ushr 1
              if (startMs[mid] <= tMs) { ans = mid; lo = mid + 1 } else hi = mid - 1
          }
          return ans
      }
      fun resolve(tUs: Long, out: ActiveSet) {
          if (n == 0) { out.aIndex = -1; out.bIndex = -1; out.type = TransitionType.NONE; return }
          val tt = tUs.coerceIn(0L, maxOf(0L, totalMs * 1000L - 1))
          val tMs = tt / 1000L
          val k = lastStartAtOrBefore(tMs)
          if (k > 0 && tMs < endMs[k - 1]) {              // overlap: transition (k-1) chal rahi hai
              out.aIndex = k - 1; out.aLocalUs = tt - startMs[k - 1] * 1000L
              out.bIndex = k;     out.bLocalUs = tt - startMs[k] * 1000L
              out.type = types[k - 1]
              out.linearP = (tt - startMs[k] * 1000L).toFloat() / (dMs[k - 1] * 1000L)
          } else {
              out.aIndex = k; out.aLocalUs = tt - startMs[k] * 1000L
              out.bIndex = -1; out.type = TransitionType.NONE; out.linearP = 0f
          }
      }
  }

LaneIndex

  class LaneIndex(lane: Lane) {
      val n = lane.items.size
      val startMs = LongArray(n) { lane.items[it].startMs }
      val endMs = LongArray(n) { lane.items[it].startMs + lane.items[it].durationMs }
      fun indexAt(tMs: Long): Int            // t par chalu item ka index, nahi to -1
      fun firstEndingAfter(tMs: Long): Int   // sabse chhota i jiska endMs[i] > tMs (nahi to n)
      fun lastStartingBefore(tMs: Long): Int // sabse bada i jiska startMs[i] < tMs (nahi to -1)
  }
  // Teeno binary search hain. Items sorted aur no-overlap hain, isliye startMs aur endMs dono ascending hain.
  // Dikhne wale items = [firstEndingAfter(leftMs) .. lastStartingBefore(rightMs)]

Niyam
- Snapshot ek baar bana to uske andar kuch nahi badalta.
- Kisi bhi consumer ko ek frame mein ek hi baar snapshot padhna hai: val s = holder.current, phir poore frame mein wahi s.
- Snapshot banne ka kaam Dispatchers.Default par, main thread par nahi.
- Purane tests (7.7 wali table: dur [5000, 4000, 6000], transitions [1000, 800], total 13200) bina badle pass hone chahiye. Time ab us mein aata hai, isliye test mein t ko 1000 se guna karo.

SECTION 6: PLAYHEAD AUR PLAYBACKCONTROLLER (EK HI WRITER)
==================================================

Kya hai
- Playhead ka time sirf PlaybackController ke andar badalta hai. Bahar ke sab ko sirf padhne wala interface (PlayheadReader) milta hai.
- Compiler isse force karta hai: likhne wali class private hai, bahar nazar hi nahi aati.

Code

  enum class PlayMode { PAUSED, PLAYING, SCRUBBING, FLINGING }

  interface PlayheadReader {
      val timeUs: Long
      val mode: PlayMode
      val generation: Int          // har seek/play/pause/scrub par badhta hai (purane results ignore karne ke liye)
  }

  interface Clock {                // abhi MasterClock, V2 mein AudioClock
      fun start(fromUs: Long)
      fun stop()
      fun timeUsAt(frameTimeNanos: Long): Long
      val isReady: Boolean         // audio clock ka pehla timestamp aane tak false
  }

  class PlaybackController(private val clock: Clock, private val holder: SnapshotHolder) {
      private class MutablePlayhead : PlayheadReader {
          @Volatile override var timeUs = 0L
          @Volatile override var mode = PlayMode.PAUSED
          @Volatile override var generation = 0
      }
      private val state = MutablePlayhead()
      val playhead: PlayheadReader = state

      // UI se (main thread). Yeh seedha time nahi badalte, sirf request rakhte hain.
      fun play(); fun pause()
      fun seekTo(us: Long)                     // seekbar tap, programmatic
      fun beginScrub()
      fun scrubBy(deltaUs: Long)               // drag ka delta (us mein, Long)
      fun endScrub(velocityUsPerSec: Double)   // fling shuru karta hai

      // Sirf FrameDriver bulata hai, har vsync par ek baar
      fun tick(frameTimeNanos: Long)
      fun needsFrames(): Boolean               // PLAYING, SCRUBBING, FLINGING, ya pending seek
  }

tick() ka kaam (har mode ke liye)
- PAUSED: kuch nahi.
- PLAYING: timeUs = clock.timeUsAt(frameTimeNanos), [0, total] mein clamp. Total par pahunche to pause.
- SCRUBBING: jo scrubBy ka jama delta hai use ek baar timeUs mein jodo (isliye ek frame mein playhead sirf ek baar badalta hai).
- FLINGING: velocity ko exponential decay se ghatao: v = v * exp(-FLING_DECAY * dt), dt = do vsync ka asli gap. timeUs += v * dt. Jab |v| * pxPerUs 20 pixel/second se kam ho to PAUSED. Edge (0 ya total) par pahunch kar turant rukta hai.
  FLING_DECAY ka shuruati value 3.0 (per second), isse feel ke hisaab se tune karna.
- Mode badalne par (play, pause, seek, scrub shuru, fling shuru) generation ek badhta hai.

Niyam
- Koi bhi aur class playhead ka time nahi likhti. Na ViewModel, na UI, na engine.
- seekTo aur scrub ke baad bhi time tick() mein hi badalta hai (ek frame ki der theek hai, par ek hi jagah badalna zaroori hai).
- Frame ke waqt har consumer val t = playhead.timeUs ek baar padhe aur poore frame mein wahi t use kare.
- timeUs ko StateFlow ya Compose state banakar composition mein padhna mana hai (R3).
- Playing mein seek hone par controller clock.start(newTime) bulata hai (MasterClock ke liye anchor, AudioClock ke liye naya audio session).

SECTION 7: FRAMEDRIVER (EK HI VSYNC, SAB KUCH ISI SE)
==================================================

Kya hai
- Poore app mein ek hi Choreographer callback hai. Timeline, preview, audio-clock sab usi frame par chalte hain, isliye aapas mein phase ka farak (jitter) nahi aata.

Code

  class FrameDriver(
      private val controller: PlaybackController,
      private val frameTick: MutableLongState,        // Compose state, sirf draw phase mein padhi jaati hai
      private val preview: PreviewRenderer
  ) : Choreographer.FrameCallback {
      private var running = false
      fun wake() { if (!running) { running = true; Choreographer.getInstance().postFrameCallback(this) } }
      override fun doFrame(frameTimeNanos: Long) {
          controller.tick(frameTimeNanos)              // playhead yahin badalta hai
          frameTick.longValue = frameTimeNanos         // timeline ka draw dobara hoga, recomposition nahi
          preview.requestRender()                      // GL thread ko batao
          if (controller.needsFrames()) Choreographer.getInstance().postFrameCallback(this)
          else running = false                         // kuch nahi chal raha to 0 CPU
      }
  }

Kab wake() bulana hai
- Play, scrub shuru, fling shuru, seek, zoom badalna, snapshot badalna (edit ke baad), selection badalna.

Niyam
- Choreographer par koi aur frame callback nahi (timeline ke liye alag, preview ke liye alag, mana).
- doFrame ke andar sirf: tick, frameTick, requestRender, repost. Koi bhaari kaam nahi.
- Idle mein (kuch nahi chal raha) callback band, CPU zero.

SECTION 8: TIMELINE CANVAS UI
==================================================

Kya hai
- Poori timeline (ruler, main track, saari lanes, playhead line) ek hi Canvas hai. Har clip ya item ke liye alag composable nahi.

Structure
- Composable: TimelineCanvas(holder, playhead: PlayheadReader, controller, zoom, frameTick, selection)
- Draw ke andar sabse pehle frameTick.longValue padho (taaki har frame draw ho), phir:
    val t = playhead.timeUs
    val s = holder.current
    val half = size.width / 2
    val offsetPx = Math.round(t * pxPerUs)              // Double -> ek hi baar integer pixel
    // koi bhi item ka x = round(startMs * 1000 * pxPerUs) - offsetPx + half
- Visible range:
    leftMs = usToMs(t - halfWidthPx / pxPerUs), rightMs = usToMs(t + halfWidthPx / pxPerUs)
    main track: lastStartAtOrBefore se k0 - 1 .. k1 + 1
    lanes: firstEndingAfter(leftMs) .. lastStartingBefore(rightMs)
- Main track ka drawing built-in MainTrackPainter karta hai. Har lane ka drawing us lane ke kind wale feature ka LanePainter karta hai (Section 10).

Scroll aur zoom
- Playhead screen ke beech mein fixed hai. Scroll ka matlab hai playhead ka time badalna. Isliye UI mein scroll ka alag koi state nahi hota (R2).
- Zoom: pxPerSecond = dp * density. Range 0.4 dp/s (poore 15 minute screen par) se 400 dp/s. Zoom sirf scale badalta hai, playhead ka time nahi, kyunki playhead beech mein fixed hai.
- Pinch ke dauraan zoom Double mein, volatile. Draw usse padhta hai. Pinch par frameTick/wake() se redraw.

Gestures (ek hi pointerInput mein)
- Horizontal drag: beginScrub, scrubBy(-dxPx / pxPerUs as Long), endScrub(velocity) (VelocityTracker se).
- Tap: x se time, phir binary search se item. Pehle junction node (48 dp touch area), phir clip, phir lane items.
- Long-press: us item ka menu (jo pehle se hai).
- Pinch: zoom.
- Drag shuru hote hi chalti fling ruk jaati hai (controller mode SCRUBBING ho jaata hai).

Hot path niyam (draw lambda ke andar)
- Koi naya object nahi: Paint, Path, Rect, Brush, list sab pehle se remember mein.
- Text ke liye TextMeasurer ka cache (key: text aur size, max 200 entries).
- Sirf visible range ka kaam.
- Pixel translate hamesha integer.

Mana hai (ye timeline ke files mein nahi ayenge)
- LazyRow, LazyColumn, rememberScrollState, ScrollState, horizontalScroll, scrollable (ye doosra scroll state bana dete hain, R2 tootta hai).
- Har clip ke liye alag composable.
- Playhead ya zoom ko composition mein padhna.
- animate*AsState se scroll chalana.

Chrome (ye alag hai, har frame nahi badalta)
- Selection, toolbar, sheet open/close, time label: ViewModel ke StateFlow se. Time label sirf tab badalta hai jab second badle.

SECTION 9: COMMANDS, UNDO AUR LIVE PARAMS (EDIT KA EK HI DARWAZA)
==================================================

Command

  interface Command {
      val label: String
      val pausesPlayback: Boolean get() = true      // zyadatar edit pehle playback roke
      val coalesceKey: String? get() = null         // same key ke lagatar commands ek undo step banate hain
      fun apply(p: Project): Project                // pure function, side effect nahi
  }

dispatch ka flow (EditorController.dispatch(cmd))
1. Agar cmd.pausesPlayback ho to playback.pause().
2. next = cmd.apply(current).
3. Validator.check(next). Fail ho to reject, UI ko reason (jaise 15 minute ki limit).
4. Undo stack mein current push (coalesceKey ho to pichle ke saath mila do).
5. Background (Dispatchers.Default) par naya TimelineSnapshot banao.
6. Main thread par: holder.current = snapshot, EditorUiState update (StateFlow), frameDriver.wake().
7. 500 ms debounce ke baad project save (Dispatchers.IO, temp file likhkar rename).
- Commands ek ke baad ek (ek hi queue) chalti hain, taaki order na bigde.
- Undo aur Redo bhi Command hain (isi rasta se jaate hain).

Live params (slider drag jaise chalte bhaav)
- Slider drag ke dauraan project ya undo ko nahi chhuna. Feature apna LiveParams rakhta hai (jaise audio ka gains array, volatile floats).
- Drag shuru se end tak: sirf LiveParams badalte hain, preview/mixer unhe padhte hain.
- Drag end par: ek Command dispatch (jaise SetVolume). Wohi ek undo step banta hai.
- LiveParams mein allocation nahi hoti (pehle se bana FloatArray).

ViewModel
- EditorUiState sirf chrome ke liye: selection, toolbar, sheet open, export state, messages.
- Playhead, time, zoom ViewModel mein nahi.

Niyam
- Koi feature seedha Project ya state nahi badalta. Sirf Command.
- Command ka apply() mein koi IO, thread ya Android call nahi.

Idea

Interfaces (core/feature/Feature.kt)

  interface Feature {

  interface FeatureRegistry {

      fun draw(ctx: PainterCtx, laneIndex: Int, from: Int, to: Int)   // sirf visible items [from..to]
  }

  interface RenderContributor {                                // GL thread
      val order: Int                                           // chhota pehle (video = 0, overlays baad mein)
      val kinds: Set<String>                                   // kin lanes par chalu item ho tab hi bulana
      fun onFrame(f: FrameCtx)                                 // f: tUs, snapshot, active, gl helpers, output size
      fun release()
  }

  interface AudioContributor {                                 // audio thread, har 10 ms block
      val kinds: Set<String>
      fun render(startFrame: Long, frames: Int, out: FloatArray)   // out mein jodta hai (add), stereo interleaved
  }

  interface Prefetcher {                                       // background thread, ~10 Hz
      fun prefetch(s: TimelineSnapshot, fromUs: Long, windowUs: Long)
  }

  interface ClipTool {                                         // clip toolbar ka tool
      val id: String
      fun appliesTo(clip: Clip): Boolean
      // icon, label, aur uska sheet (Composable) yahin se
  }

Core feature ko kaise bulata hai
- Snapshot banne par core "kind -> lane indexes" ki table bana leta hai.
- Har frame mein core active.laneItem se dekhta hai ki kis kind ke lane par item chalu hai. Sirf unhi features ke contributors ko bulata hai (kinds ke hisaab se). Jis feature ka kuch chalu nahi, uska kharcha zero (bas ek check).
- Built-in cheezein bhi isi contract se jodo: video renderer (order 0), clip ka audio (AudioContributor), main track ka painter.

Failure isolation
- Contributor mein exception aaye to pakad kar log karo aur us contributor ko us session ke liye band karo. App crash nahi.
- Har contributor ka time System.nanoTime se naapo (FrameBudget, Section 11).

Registration
- Ek hi file Features.kt mein list: listOf(AudioFeature, TextFeature, ...). Naya feature = ek line.

SECTION 11: THREADS AUR FRAME BUDGETS
==================================================

Thread ki zimmedari

  Main thread   : gestures, FrameDriver, timeline draw, ViewModel. Koi IO, decode, JSON nahi.
  GL thread     : PreviewRenderer, RenderContributors. updateTexImage, draw.
  Audio thread  : mixer, AudioTrack write (V2).
  Decode thread(s): har decoder ka apna HandlerThread (Phase 0 jaisa).
  Default pool  : snapshot build, prefetch loop.
  IO pool       : save, import copy, metadata.

Data thread ke beech kaise jaata hai (sirf yeh tareeke)
- Immutable snapshot (SnapshotHolder.current, volatile reference).
- Volatile primitives (playhead.timeUs, mode, generation, LiveParams ke floats).
- SPSC ring buffers (audio PCM, decoded frame queues).
- Command queue (UI se EditorController tak).
- Lock wala shared mutable state mana hai.

Frame budgets (60 Hz par frame = 16.6 ms; release build, mid-range phone)

  Timeline draw (poora Canvas)            : p99 4 ms se kam
  Har LanePainter (100 dikhte items par)  : 1 ms se kam
  GL thread poora frame (preview)         : p99 8 ms se kam
  Audio ka 10 ms block render             : 2 ms se kam
  Snapshot build (900 clips + 1000 items) : 50 ms se kam (background)
  snapshot.resolve (ek baar)              : 50 microsecond se kam
  Main thread par koi bhi akela kaam      : 4 ms se kam

FrameBudget (debug build mein)
- Har contributor aur painter ka nanosecond time pehle se bane array mein jama hota hai (allocation nahi).
- Har 10 second par ek log line: kis ka p50, p99, max. Jo budget todta hai uska naam aata hai. Isse pakad mein aata hai ki kaun sa feature dosi hai.

Kyun

Kya pakda jaata hai

  1. core/ mein android.* import, ya androidx.* import (sirf compose.runtime.Immutable / Stable allowed).
  2. ui/timeline/ mein LazyRow, LazyColumn, rememberScrollState, ScrollState, horizontalScroll, scrollable(.

Sample script (app/build.gradle.kts mein). Ye abhi test nahi hua hai, pehli baar chalakar dekhna, syntax error aaye to agent se sirf syntax theek karwana.

  tasks.register("checkRules") {
      doLast {
          val src = file("src/main/java/com/flowcut/app")
          val errors = mutableListOf<String>()
          fun scan(dir: String, rules: List<Pair<Regex, String>>, skip: Set<String> = emptySet()) {
              val d = File(src, dir)
              if (!d.exists()) return
              d.walkTopDown()
                  .filter { it.isFile && it.extension == "kt" && it.name !in skip }
                  .forEach { f ->
                      f.readLines().forEachIndexed { i, line ->
                          rules.forEach { (rx, msg) ->
                              if (rx.containsMatchIn(line)) errors += "${f.relativeTo(src)}:${i + 1}: $msg"
                          }
                      }
                  }
          }
          scan("core", listOf(
              Regex("""import android\.""") to "core mein android import mana hai",
              Regex("""import androidx\.(?!compose\.runtime\.(Immutable|Stable)\b)""") to "core mein androidx import mana hai",
              Regex("""import com\.flowcut\.app\.(engine|ui|features|audio)""") to "core upar ki layer ko import nahi kar sakta"
          ))
          scan("ui/timeline", listOf(
              Regex("""\b(LazyRow|LazyColumn|rememberScrollState|ScrollState|horizontalScroll)\b|scrollable\(""") to "timeline mein doosra scroll state mana hai"
          ))
          for (dir in listOf("core", "engine", "audio", "ui")) {
              scan(dir, listOf(Regex("""Thread\.sleep|runBlocking""") to "sleep/runBlocking mana hai"))
          }
          for (dir in listOf("core", "engine", "audio", "ui", "features")) {
              scan(dir, listOf(Regex("""\.timeUs\s*=[^=]""") to "playhead ka time sirf PlaybackController likhta hai"),
                   skip = setOf("PlaybackController.kt"))
          }
          if (errors.isNotEmpty()) throw GradleException(errors.joinToString("\n"))
      }
  }
  tasks.matching { it.name == "preBuild" }.configureEach { dependsOn("checkRules") }

Niyam 5 (features ek doosre ko import nahi karte) script mein abhi nahi hai. Feature packages banne par ek aur scan add karna.
Jo niyam grep se nahi pakde ja sakte (hot path mein allocation, composition mein playhead padhna) unhe code review mein dekho (Section 16 ka checklist) aur FrameBudget ke numbers se.
